# 测试集统计（eval_stats）

## 规模与分布（30 题试点）

| 题型 | 数量 | 占比 | 示例 |
|---|---|---|---|
| 事实型 | 8 | 26.7% | TTL 字段的作用、IPv6 地址记法 |
| 对比型 | 8 | 26.7% | TCP vs UDP、递归查询 vs 迭代查询 |
| 过程型 | 8 | 26.7% | 三次握手、CRC 校验过程、拥塞处理 |
| 多跳型 | 4 | 13.3% | 为何 DNS 用 UDP 而 FTP 用 TCP、IP/MAC 地址跨网变化 |
| 计算型 | 2 | 6.7% | 发送时延计算、慢开始 cwnd 增长 |

覆盖全部 6 章；多跳型证据跨章节标注（最多 3 条/题）。

## 每题字段规范（questions.jsonl）

| 字段 | 说明 |
|---|---|
| `id` | q001–q030 |
| `type` | 事实型/对比型/过程型/多跳型/计算型 |
| `difficulty` | 低/中/高 |
| `question` | 自然语言问题 |
| `gold_answer` | 标准答案（人工撰写） |
| `gold_evidence` | 语料**原文逐字片段**（1–3 条），从 `data/raw/` 复制，用于计算 HitRate@k / Recall@k / MRR |
| `key_points` | 2–6 字关键词，用于计算答案关键点覆盖率 |

## 质检结果（2026-10-03）

- 证据匹配：**30/30**——每条 gold_evidence 经归一化（去空白与标点）后均能在语料中逐字命中
- 关键点覆盖率：全部题目 **1.00**（key_points 均出现在 gold_answer 中）
- 质检脚本逻辑：`src/metrics.py`（normalize / hit_rate_at_k / recall_at_k / mrr / keypoint_coverage）

试点通过后扩展至 **150–300 题**：以王道课后习题与 408 真题改编为主，保持题型配额；计算题单列，用于错误分析章节。
