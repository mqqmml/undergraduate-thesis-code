## 1. 四个必答问题

### 1.1 我要和谁比较？（对照组设置）

比较分三个层次，每层只回答一个问题：

| 层次 | 对照组 | 实验组 | 回答什么问题 |
|---|---|---|---|
| 生成层（RAG 是否必要） | C0：不检索，直接问 qwen3:4b | C1：朴素 RAG Baseline | 检索增强本身带来多少增益？ |
| 检索层（哪种检索更好） | C1：单一稠密向量检索（nomic-embed-text + FAISS） | C2a：BM25 关键词检索<br>C2b：混合检索（稠密 + BM25，RRF 融合）<br>C2c：稠密检索 + Rerank 重排 | 检索方案的差异有多大？增益来自召回还是排序？ |
| 组件层（消融） | C1 / 各实验自身去掉该组件的版本 | 更换 chunk_size、top_k、embedding、query rewrite、agentic 循环 | 每个设计因素的边际贡献是多少？ |

**关于 C0（无检索裸 LLM）**：必须补上。它是论文里"垂直领域幻觉"论断的直接证据，也是"RAG 有效"的最基本对照。用同一个 qwen3:4b、同一套 30 题，prompt 只去掉资料部分，指标只算 KeyPointCoverage（检索指标无意义）。

**对照组命名规范**：`E1-dense`（复现 Baseline）、`E1-bm25`、`E1-hybrid`、`E1-rerank`，配置即实验，结果目录同名。

### 1.2 测哪些指标？

分三层，每层都有主指标和辅指标，避免"指标太多但都不知道说明什么"。

| 层 | 指标 | 定义 | 现状 |
|---|---|---|---|
| 检索 | **HitRate@k**（主） | top-k 内是否含任一 gold_evidence | ✅ 已实现 |
| 检索 | **Recall@k** | top-k 命中证据数 / 该题全部证据数（多证据题有区分度） | ✅ 已实现 |
| 检索 | **MRR**（主） | 第一条命中证据排名的倒数 | ✅ 已实现 |
| 检索 | nDCG@k、MAP | 考虑排序位置的加权指标 | ⬜ 待补（可选） |
| 检索 | 召回上限 Recall@100 | 候选池够大时能否找到（用于分离"召回"与"排序"） | ✅ 已用（见分析报告） |
| 生成 | **KeyPointCoverage**（主） | 答案覆盖标准答案关键点的比例 | ✅ 已实现（口径待修，见 3.4） |
| 生成 | **CitationRate** | 答案中带 `[片段x]` 标注的比例（可溯源规范性） | ✅ 已实现 |
| 生成 | **Faithfulness**（主） | 答案每个论断是否有上下文支撑（无幻觉） | ⬜ 待引入 |
| 生成 | Answer Correctness / 完整度 | 与 gold_answer 的语义一致性与要点完整度 | ⬜ 待引入（裁判模型 + 人工抽检） |
| 系统 | 拒答率 | 回答"资料中没有相关信息"的比例 | 🟡 可从现有 CSV 统计 |
| 系统 | 平均延迟 / 索引成本 | 端到端响应时间、建索引耗时 | 🟡 部分有（本次 30 题 1533 s，约 51 s/题） |

**Faithfulness 的实施方案（需在开题前定下来）**：
- 首选 RAGAS 的 faithfulness + answer relevancy，裁判模型用本地 qwen3:4b；
- 4B 模型做裁判稳定性存疑，**必须**配人工校准：随机抽 30 题，人工双标注，报告裁判与人工的一致性（Cohen's kappa）；kappa < 0.6 则改用更强裁判（云端 API）或改为规则化指标；
- 论文中同时报告规则化指标（KPC / CitationRate，可完全复现）与裁判指标（Faithfulness，标注校准），互为交叉验证。

### 1.3 每个实验改变什么变量？

**核心原则：一个实验只动一个变量，其余全部冻结。**

| 实验 | 自变量（只动这个） | 控制变量（冻结） | 因变量 |
|---|---|---|---|
| E0 Baseline | — | chunk 512 / overlap 50 / nomic-embed-text / dense / top-k 5 / qwen3:4b / temp 0 | 全部指标 |
| E1-bm25 | 检索方式 = BM25（jieba 分词） | 同上（chunk 与 top-k 不变） | 检索 + 生成指标 |
| E1-hybrid | 检索方式 = dense + BM25 融合 | 同上 | 同上 |
| E1-rerank | 增加 Rerank 阶段（候选 50 → 重排取 5） | 同上 | 同上 |
| E2-chunk | chunk_size ∈ {256, 512, 1024} × overlap ∈ {0, 50, 100} | embedding / top-k / prompt 不变 | 同上（每组需重建索引） |
| E2-topk | top_k ∈ {3, 5, 10, 20} | chunk / embedding 不变 | 同上 + 上下文长度 |
| E2-embed | embedding ∈ {nomic-embed-text, bge-m3, bge-large-zh} | chunk / top-k / prompt 不变 | 同上（每组需重建索引） |
| E2-split | 切分策略 ∈ {recursive, 按标题语义切} | size 尽量对齐 | 同上 |
| E3-rewrite | 是否启用 Query Rewrite | 检索方案固定在最优组合 | 端到端指标 |
| E3-agentic | 是否启用迭代检索（多跳分解） | 同上 | 端到端指标 + 延迟 |
| E0-norag | 是否检索（C0） | 同一 LLM / 同题 | 仅生成指标 |

**重复与随机性**：temperature=0 保证生成可复现，因此每题跑 1 次；对差异接近判据阈值的实验（差值 < 5 个百分点）补跑 3 次取均值并报告方差。检索阶段本身无随机性，无需重复。

### 1.4 什么结果能够证明我的方法/系统有效？

**先写判据，再跑实验**（避免事后挑有利数据）：

| 层次 | 成功判据（预设） | 依据 |
|---|---|---|
| 检索层 | HitRate@5 ≥ **0.70**（Baseline 0.467），MRR ≥ **0.50**（Baseline 0.276） | 召回上限已达 0.867，说明排序环节有 40 个百分点可争取；取"兑现一半以上"为目标 |
| 检索层 | 相对提升 ≥ **20%** 且配对检验 **p < 0.05** | 30 题样本小，用 Wilcoxon 符号秩检验 + bootstrap 1000 次重采样置信区间；同时报告效应量（Cliff's delta），避免只报 p 值 |
| 生成层 | KeyPointCoverage ≥ **0.70**（口径修正后）、Faithfulness ≥ **0.85** | 修正 key_points 匹配口径后再定基线，0.70 对应"大部分关键点都说到" |
| 生成层 | 拒答率 ≤ **10%**（当前 q011 类误拒答需消除） | 证据已进上下文却拒答，属于系统缺陷而非能力上限 |
| 端到端 | 失败率从 56.7% 降到 ≤ **25%** | 失败类型可归因，逐类消除 |
| 组件有效性 | 加 Rerank 相对无 Rerank 的 HitRate@5 提升 ≥ **5pp** | 低于此值判定为"无实质增益" |
| **反向判据** | 若某策略相对提升 < 5pp，或 bootstrap 区间跨 0，则如实报告为**无效策略**并分析原因 | 防止"为了证明有效而反复调参"，这是实验诚实性要求 |

## 2. 实验纪律与可复现性

1. **配置即实验**：所有超参写在 `configs/<实验名>.yaml`，代码中不出现任何硬编码超参；新增实验 = 新增一个 yaml。
2. **结果目录约定**：`results/<实验名>/{summary.json, per_question.csv, retrieval_log.jsonl}`，实验名与配置文件 `name` 字段一致。
3. **评测集冻结**：当前 30 题冻结为 **v1.0**，所有 E0–E3 实验均在其上比较；扩充到 150–300 题后另立 **v2.0**，两版结果分开报告，不混用。
4. **语料与索引版本**：语料为 6 章 OCR Markdown（373,650 字符），重建索引时记录 chunk 总数与参数；建议后续补记语料文件哈希（md5）以支持"同一切分下的严格复现"。
5. **生成可复现**：temperature=0、固定 prompt 模板；prompt 一变即视为新实验，不允许在对比实验中途修改 prompt。
6. **一次只动一个变量**：E2 的五个子实验必须串行执行，禁止同时改 chunk 与 embedding。
7. **结论门槛**：任何"某某更优"的结论必须附（a）配置路径（b）样本量（c）效应量与区间（d）失败案例反例。

## 3. 实验清单（详细设计）

### E0 — Baseline 复现（已完成）

- **目的**：固定一套朴素 RAG 流程作为后续所有实验的参照系，同时定位第一版瓶颈。
- **配置**：`configs/baseline.yaml`（chunk 512/50、nomic-embed-text、FAISS dense、top-k 5、qwen3:4b、temp 0）
- **数据**：语料 373,650 字符 → 1078 个 chunk；评测集 30 题（事实 8 / 对比 8 / 过程 8 / 多跳 4 / 计算 2）
- **结果**：HitRate@5 = 0.467、MRR = 0.276、KPC = 0.436、CitationRate = 0.60；失败分布 retrieval_miss 43.3% / ok 30% / generation_miss 16.7% / rank_miss 10%
- **复现命令**：
  ```bash
  python -m src.index                                  # 建索引（分批嵌入 32）
  python -m src.evaluate                               # 检索 + 生成 + 指标（约 25 min）
  python -m src.evaluate --no-gen                      # 只评检索（秒级）
  ```
- **结论**：见 [Baseline 问题分析报告](baseline_problem_analysis.md)——瓶颈在**排序**而非召回，根因指向 embedding 中文区分度不足。

### E1 — 主实验：检索方案对比

同一条生成链路（qwen3:4b + 同一 prompt + top-k 5），只换检索方案，回答"两种有显著区别的检索方案孰优"（任务书要求 3）。

| 子实验 | 实现要点 | 预期 |
|---|---|---|
| E1-dense | 复现 Baseline（作为参照） | HitRate@5 = 0.467 |
| E1-bm25 | `rank_bm25` + jieba 分词；中文必须分词，否则 BM25 退化为字符匹配 | 术语型/事实型更强，对比型较弱 |
| E1-hybrid | dense 与 bm25 各取 20，RRF（k=60）融合后取 5 | 期望优于任一单路 |
| E1-rerank | dense 召回 50 → 交叉编码器重排（bge-reranker-base）→ 取 5 | **重点**：候选池召回上限 0.867，理论上限即为 Rerank 的可达空间 |
| （可选）E1-norag | 无检索直接生成 | 建立"必须用 RAG"的证据 |

**判据**：主实验中最优方案相对 E1-dense 的 HitRate@5 提升 ≥ 20%（p < 0.05），且 MRR 同步提升。
**记录要求**：每个方案同时报告 top-5 与 top-50（或 100）召回，用于说明是"召回提升"还是"排序提升"。

### E2 — 消融 / 参数实验

| 子实验 | 取值范围 | 关注点 |
|---|---|---|
| E2-chunk | 256 / 512 / 1024（× overlap 0 / 50 / 100） | 定义句、公式段是否被切散；当前 q001/q003 的定义型失败是否由切分粒度导致 |
| E2-topk | 3 / 5 / 10 / 20 | 召回随 k 的增益曲线；k 越大上下文噪声越多，生成反而可能变差（测生成指标交叉验证） |
| E2-embed | nomic-embed-text / bge-m3 / bge-large-zh | **最高优先级**：直击"相似度无区分度"这一根因；换模型需重建索引 |
| E2-split | recursive 512 vs 按 `##` 标题语义切 | 语义完整性对生成质量的影响 |
| E2-prompt（可选） | 当前模板 vs 对比型专用模板（要求分点并列作答） | 针对对比型 KPC = 0.12 的问题 |

**判据**：能给出"chunk size / top-k / embedding 各自对 Recall 与生成质量的边际影响曲线"，并在论文中呈现趋势图（至少 3 个取值才能画趋势）。

### E3 — 检索策略优化（拓展目标）

| 子实验 | 方法 | 针对的失败类型 |
|---|---|---|
| E3-rerank | 见 E1-rerank（如已在主实验完成则引用） | rank 排后的 9 题 |
| E3-rewrite | 把用户问题改写为检索友好形式：对比型拆成"A 是什么/B 是什么/二者区别"子查询；多跳型拆成顺序子问题 | 对比型生成失败、多跳型跨章证据 |
| E3-agentic | 迭代检索：先检索 → 判断证据是否充分 → 不足则改写再检索（多跳题最多 3 轮） | 4 道真·检索失败题中的跨章题（如 q027） |
| E3-hyde（可选） | 假设文档嵌入（先让 LLM 生成假想答案再检索） | 短问题/定义型问题（q001） |

**判据**：端到端 KeyPointCoverage 与 Faithfulness 提升 ≥ 20%，同时报告延迟与调用成本增量（Agentic 的代价必须量化，否则不能声称"优化"）。

### E4 — 异常与失败案例分析

- **抽样方案**：按 (题型 × 失败类型) 分层，每格抽 2 题；Baseline 阶段共 13+5+3 = 21 题失败，全量分析（样本量允许）。
- **根因编码表**（固定 7 类，避免每次自由发挥）：

  | 编码 | 含义 |
  |---|---|
  | R1 | 召回缺失：候选池内无正确证据 |
  | R2 | 排序偏后：证据在池内但排名超出 top-k |
  | R3 | 切分破坏：证据被切断或与上下文割裂 |
  | R4 | 语料噪声：OCR 错字 / 公式失真 / 水印 |
  | G1 | 拒答：证据已给但回答"资料中没有" |
  | G2 | 遗漏：答案方向正确但关键点缺失 |
  | M1 | 度量误判：答案正确但指标判定失败 |

- **产出**：每类 2–3 个案例卡片（问题 / 检索到的片段 / 生成答案 / 期望答案 / 根因 / 改进动作），并给出根因分布饼图（论文错误分析章节直接用）。
- **判据**：每个根因都有对应的改进实验，并且改进实验后该根因占比下降（形成闭环）。

## 4. 进度与下一步

| 阶段 | 内容 | 状态 |
|---|---|---|
| 阶段一 | 领域确定 + 知识库 + 评测集（30 题 v1.0） | ✅ |
| 阶段二 | Baseline 全链路跑通 + 问题分析 | ✅（评测完成，分析报告 v1 已完成） |
| 阶段三 | E1 主实验 + E2 消融 | ⬜ 下一步 |
| 阶段四 | E3 优化（Rerank / Rewrite / Agentic） | ⬜ |
| 阶段五 | 失败案例闭环 + 论文撰写 | ⬜ |

**建议执行顺序（按"根因优先"而非"实现难易"）**：
1. **E2-embed（换 bge-m3）** —— 直击最根本根因，成本低（仅重建索引），可能一次性抬高所有指标；
2. **E1-rerank** —— 召回上限 0.867 的差距主要靠排序兑现，实现成本中等；
3. **E2-chunk** —— 验证"切分粒度"对定义型/计算型失败的影响；
4. **E1-bm25 / E1-hybrid** —— 补齐"两种有显著区别的检索方案"的任务书硬要求；
5. **E3-rewrite → E3-agentic** —— 针对对比型与多跳型；
6. **指标口径修正**（KPC 关键词匹配、gold 证据匹配）应**先于**上述实验完成，否则后续所有对比都建立在有偏的度量上。

## 5. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 30 题样本量小，指标波动大 | 结论不稳，答辩被质疑 | bootstrap 置信区间 + 配对检验；中期前扩到 150–300 题（v2.0） |
| 指标口径有偏（KPC 逐字匹配、gold 证据片段匹配） | 系统性低估/高估，误导优化方向 | 先修口径（见分析报告第十一节），再做对比实验 |
| 裁判模型（qwen3:4b）判 Faithfulness 不稳 | 生成指标不可信 | 人工双标注校准 + 报告一致性；必要时改用更强裁判 |
| 本地无 GPU，qwen3:4b 推理慢（约 51 s/题） | 组合实验时间成本高（每个生成实验 ≈ 25 min） | 检索类实验一律先跑 `--no-gen`（秒级）筛选，只对入围配置跑完整评测 |
| OCR 语料公式/图表失真 | 计算题无法公平评测 | 计算题单列统计，不混入总均值；论文 limitation 明示 |
| 换 embedding 需重建索引 | 遗漏旧索引导致结果不可比 | 索引目录按实验名分离（`index/<实验名>/`），配置文件锁定 persist_dir |
