# Baseline 问题分析报告（v1）

> 对象：朴素 RAG Baseline（固定切分 + 单一稠密检索 + 固定 top-k + 直接生成）
> 数据：`results/baseline/`（30 题 v1.0 评测集，2026-10-06 完整评测含生成，耗时 1533 s）
> 依据配置：`configs/baseline.yaml` ｜ 配套：[实验设计](experiment_design.md)
> 状态：第一版。结论基于 30 题样本，样本扩充至 v2.0 后需复算。

> **⚠️ 后续更新（2026-10-07）**：本报告的 30 题结论已在 **238 题 eval-v2.0** 上复算，口径修正（top-50 检索深度、chunk-level gold、KPC 分词重叠、Faithfulness）已全部落地。
> 复算后的正式基线为：HitRate@5=0.265 / @50=0.656 / MRR=0.164 / KPC=0.494 / CitationRate=0.500 / Faithfulness=0.339；
> 失败类型 `rank_miss` 39.1% > `retrieval_miss` 34.5% > `ok` 21.4% > `generation_miss` 5.0%。
> 本报告第一节"排序问题题数是召回问题 2.25 倍"的核心判断在大样本上得到验证（93 vs 82）。
> 最新数据见 `results/baseline_v2/`、`data/metadata/eval_stats.md`、`evaluation/README.md` 第六节。

## 一、结论摘要

1. **检索是主瓶颈，但"检索失败"必须拆成两类。** 13 道 top-10 未命中的题里，**9 道在 top-100 内可以找回**（排名 12–99），只有 **4 道是真·检不到**（q001、q003、q023、q027）。也就是说，**排序问题的题数是召回问题的 2.25 倍**。
2. **检索的真实上限远高于当前水平。** top-100 命中 26/30 = **0.867**，而 HitRate@5 只有 **0.467**——约 40 个百分点丢在"排序"这一环，而不是"找得到找不到"。这直接解释了为什么 Rerank 应当是本课题收益最高的单点改进。
3. **根因指向 embedding 模型的语义区分度，而不是代码或流程。** 30 题 top-1 余弦相似度全部挤在 **0.661–0.889**（标准差仅 0.049）；更严重的是，**4 道真失败题中检索到的无关段落平均余弦 0.764，高于 9 道部分失败题中正确答案的 0.681**——正确证据在相似度上根本压不过无关文本。`nomic-embed-text` 面向英文训练，中文语义区分能力不足。
4. **生成层的 5 例"生成失败"里有 3 例是度量误判。** q012 / q013 / q017 的答案要点其实基本正确，是 `KeyPointCoverage` 的**逐字关键词匹配**（答案用"链路状态数据库"而 key_points 要求"完整的全网拓扑结构图"）判成了 0 分，导致 KPC 0.436 被系统性低估。
5. **真正值得警惕的生成缺陷是"误拒答"。** q011（DNS 递归 vs 迭代）的证据就在检索结果 **rank 2**，模型却回答"资料中没有相关信息"。证据进了上下文却说不出来，属于系统缺陷而非模型能力上限，必须消除。
6. **题型分化明显**：对比型检索命中率与事实型相同（0.50），但要点覆盖率只有 **0.12**（事实型 0.70）；计算型 **2/2 检索全灭**（排名 63 / 99），与 OCR 公式失真、切分把题干切散直接相关。

## 二、实验设置（可复现）

| 项 | 内容 |

| 指标 | 值 |
|---|---|
| HitRate@1 / @3 / @5 / @10 | 0.133 / 0.367 / **0.467** / 0.567 |
| Recall@1 / @5 / @10 | 0.094 / 0.306 / 0.394 |
| MRR | 0.276 |
| KeyPointCoverage | 0.436 |
| CitationRate | 0.60 |
| 平均单题耗时 | 51.1 s（本地 CPU 推理 qwen3:4b） |

**失败类型分布**（`failure_type` 判定，见 `src/metrics.py::classify_failure`）：

| 类型 | 题数 | 占比 | 含义 |
|---|---|---|---|
| retrieval_miss | 13 | 43.3% | top-10 内未命中任何证据 |
| ok | 9 | 30.0% | 命中且要点覆盖 ≥ 0.6 |

## 四、分题型分析

| 题型 | n | HitRate@5 | HitRate@10 | KeyPointCoverage | CitationRate | 一句话结论 |
|---|---|---|---|---|---|---|
| 事实型 | 8 | 0.50 | 0.62 | **0.70** | 0.88 | 表现最好；但最基础的定义题（q001）反而检索失败 |
| 对比型 | 8 | 0.50 | 0.50 | **0.12** | 0.38 | 检索命中率不低，**生成端几乎全军覆没**：检索到了也做不出对比 |
| 过程型 | 8 | 0.50 | 0.62 | 0.47 | 0.62 | 中等；步骤类答案易遗漏收尾环节（如 q028 漏 ARP） |
| 多跳型 | 4 | 0.50 | 0.75 | 0.38 | 0.50 | top-10 表现最好但生成弱：证据跨章分散，单次检索难集齐 |
| 计算型 | 2 | **0.00** | **0.00** | 0.62 | 0.50 | 检索全灭（排名 63 / 99），公式与题干被切散 / OCR 失真 |

**值得注意的错位**：五种题型的 HitRate@5 全是 0.50（差异来自分组内部的随机性），但 KPC 从 0.70 跌到 0.12。**说明当前的检索指标已无法区分题型难度，瓶颈已经转移到生成端和排序端**；继续只在"检索命中率"上做优化，边际收益有限。

## 五、诊断一：排序问题 > 召回问题

把 k 放大到 100 后逐题复算首条命中证据的排名：

| 题号 | 题型 | 原 top-10 | top-100 内排名 | 判定 |
|---|---|---|---|---|
| q008 | 事实型 | 未命中 | 12 | 排序偏后 |
| q018 | 过程型 | 未命中 | 12 | 排序偏后 |
| q016 | 对比型 | 未命中 | 17 | 排序偏后 |
| q019 | 过程型 | 未命中 | 17 | 排序偏后 |
| q015 | 对比型 | 未命中 | 45 | 排序偏后 |
| q030 | 计算型 | 未命中 | 63 | 排序严重偏后 |
| q010 | 对比型 | 未命中 | 66 | 排序严重偏后 |
| q014 | 对比型 | 未命中 | 88 | 排序严重偏后 |
| q029 | 计算型 | 未命中 | 99 | 贴在 100 边界 |
| q001 | 事实型 | 未命中 | **未找到** | 真·检索失败 |
| q003 | 事实型 | 未命中 | **未找到** | 真·检索失败 |
| q023 | 过程型 | 未命中 | **未找到** | 真·检索失败 |
| q027 | 多跳型 | 未命中 | **未找到** | 真·检索失败 |

**汇总**：

- top-10 未命中 13 题 → 其中 **9 题（69%）在 top-100 内找回**，4 题真失败
- 召回上限（top-100 命中率）= 26/30 = **0.867**，对比 HitRate@5 = 0.467，差距 **40 个百分点**
- 对比型 4 道未命中题的排名分别是 17 / 45 / 66 / 88——**对比型问题整体排序质量最差**

**解释**：对比型问题问的是"A 和 B 的区别"，而语料中 A 与 B 往往分布在相隔较远的段落，单段文本与整句 query 的词面/语义重叠度都不高，于是既不像 A 也不像 B，被大量"部分相关"的段落淹没。这正是 **Query Rewrite（把"A 和 B 有什么区别"拆成 A、B 两个子查询）+ Rerank** 的直接动机。

## 六、诊断二：embedding 相似度无区分度（核心根因）

按"正确证据的排名"把 30 题分组，统计 top-1 命中段落与正确证据段落的余弦相似度：

| 分组 | n | top-1 余弦（均值） | 正确证据余弦（均值） |
|---|---|---|---|
| A：正确证据进 top-5 | 14 | 0.806 | 0.788 |
| B：正确证据排名 6–10 | 3 | 0.835 | 0.773 |
| C：正确证据排名 11–100 | 9 | 0.787 | **0.681** |
| D：正确证据 100 名之外（真失败） | 4 | **0.764**（该题检索到的**无关**段落） | — |

**三组数字放在一起，问题就暴露了**：

1. **D 组无关段落的相似度（0.764）高于 C 组正确答案的相似度（0.681）。** 模型给出的"最相似段落"里，完全不相关的内容比真正正确的证据更"像"问题答案。
2. **30 题 top-1 余弦全部落在 0.661–0.889，标准差仅 0.049。** 相关与不相关的相似度分布几乎重叠，**这个分数已经不能作为相关性判据**。
3. 能找回的 26 题里，正确证据余弦最低只有 **0.601**——比某些题目的无关 top-1 还低。

**典型个案（q001「什么是计算机网络？」）**：

- gold_evidence：`一般认为，计算机网络是将众多分散的、自治的计算机系统，通过通信设备与线路连接起来，并由功能完善的软件实现资源共享和信息传递的系统。`（教材最基础的定义句）
- 实际 top-1（余弦 0.6788 → cos 0.66）：`03-数据链路层.md#c0141` —— 内容却是 CSMA/CD 冲突退避的描述：`。直到 t=t 时，B 站检测到冲突并停止发送…`
- 相似度最高的一题，检索结果却是完全不相干的章节内容。

**归因**：`nomic-embed-text` 是英文语料为主训练的 137M 模型，对中文语义的判别力有限；配合"固定字符数切分"产生的残缺片段，向量表征进一步失真。**这是当前 Baseline 最主要、也最容易验证的根因**——换 `bge-m3` / `bge-large-zh` 重建索引（约 1 小时）即可对照检验，无需改代码逻辑。

## 七、诊断三：切分与语料质量问题

1. **chunk 开头是上一块的残句。** recursive 切分 + overlap 50 导致大量 chunk 以半句话开头，例如 q001 的 top-1：`。直到 t=t 时，B 站检测到冲突并停止发送。`——开头就是句号与截断的语义。这会显著稀释该 chunk 的向量表征，是"排序偏后"的成因之一。
2. **定义句被切散。** q001 的定义句、q003 的 TTL 定义句所在 chunk 都未能进入 top-100，而 top-1 命中的却是同章节里"更碎、更具体"的内容（如 TTL 相关 chunk 命中的是 IPv6 首部改动的段落）。粒度与语义完整性之间存在明显冲突。
3. **OCR 噪声**：chunk 文本中残留水印碎片（如 `KUKU`）、公式与二进制运算失真、图表 caption 混入正文（`data/metadata/corpus_manifest.md` 已记录）。
4. **计算型全灭的直接后果**：q029（发送时延计算）、q030（慢开始 cwnd 增长）排名 99 与 63，题干与公式在 OCR + 切分双重损失下已难以与 query 对齐。**建议计算类题目单列统计**，不混入总均值，以免用"OCR 缺陷"污染"检索策略优劣"的结论。

## 八、诊断四：生成阶段问题

5 例 `generation_miss` 逐题核查（人工判别真实成因）：

| 题号 | 题型 | KPC | 真实情况 | 根因编码 |
|---|---|---|---|---|
| q011 | 对比型 | 0.00 | 答案 = "资料中没有相关信息"；而正确证据在**检索结果 rank 2** | **G1 误拒答** |
| q012 | 对比型 | 0.00 | 答案分 3 点、结构清晰、内容正确（"拓扑信息掌握 / 路由计算机制 / 问题避免"），仅措辞与 key_points 不同（如"链路状态数据库"vs"完整的全网拓扑结构图"） | **M1 度量误判** |
| q013 | 对比型 | 0.00 | 答案正确但过简（奈氏/香农适用信道与限制均说到），未出现 key_points 的字面词（"理想低通信道""2W 波特"） | **M1 度量误判** |
| q017 | 过程型 | 0.25 | 三次握手三步齐全、含 SYN/ACK/seq 细节，且模型主动指出原文表述错误并修正，属高质量回答 | **M1 度量误判** |
| q028 | 多跳型 | 0.25 | IP 不变 / MAC 每跳改写两点正确，**遗漏 ARP 获取目的 MAC 的环节**——该信息不在本次检索到的片段里 | **G2 遗漏（证据缺失导致）** |

**结论**：

- 真正的生成能力失败只有 2 例（q011 误拒答、q028 证据缺失），其余 3 例是指标误判。
- **`KeyPointCoverage` 与人工判断严重不符**，原因是它用"关键点字符串归一化后逐字包含"判定，对**改写、缩写、同义表达**零容忍。修正后 KPC 会明显上升，Baseline 的"生成质量"实际好于 0.436 这个数字。
- **CitationRate = 0.60**：40% 的答案没有 `[片段x]` 标注，可溯源性不达标（prompt 里已明确要求，说明 4B 模型对格式指令的遵循不稳定）。
- **误拒答（q011）值得单独深挖**：证据在 rank 2 却拒答，可能是 top-5 上下文中包含 3 个以上无关片段（对照第五节，该题正确证据余弦仅约 0.68），噪声压过了有效信息，使模型判定"资料不含相关信息"。这个问题会随着 Rerank 与更好的 embedding 自然缓解，但在 prompt 层面也应补充"资料中若存在部分相关信息，请基于已有的部分作答"的指令。

## 九、根因归纳与对策映射

| 根因 | 证据 | 对策实验 | 预期收益 |
|---|---|---|---|
| **R2 排序偏后** | 9 题排名 11–100；召回上限 0.867 vs HitRate@5 0.467 | E1-rerank（候选 50 → 交叉编码器重排）；E2-topk | 最高。HitRate@5 有望逼近 0.70 |
| **Embedding 中文区分度不足** | top-1 余弦区间 0.661–0.889（σ=0.049）；无关段落 0.764 > 正确答案 0.681 | E2-embed（bge-m3 / bge-large-zh） | 高。可能一次性抬高全部指标 |
| **R3 切分残缺 / 边界破坏** | chunk 以残句开头；定义句被切散（q001、q003） | E2-chunk（256/512/1024）、E2-split（按标题语义切） | 中高，尤其利于事实型与计算型 |
| **R1 真·召回缺失** | q001、q003、q023、q027 在 top-100 外 | E3-rewrite、E3-hyde、E3-agentic | 中。主要利好多跳与短问题 |
| **R4 语料 OCR 噪声** | 公式/表格失真；水印 `KUKU`；计算题 2/2 失败 | 换非扫描版教材或按章补录；计算题单列统计 | 中（可解释性收益大于指标收益） |
| **G1 误拒答** | q011 证据在 rank 2 却答"资料中没有相关信息" | prompt 增加"部分信息也可作答"指令；Rerank 降噪 | 中，但影响体验与可信度 |
| **M1 度量误判** | q012 / q013 / q017 答案正确却判 0 分 | 修正 KPC 匹配口径（见第十一节） | **前置必做**，否则后续对比全部有偏 |

## 十、结论与后续优先级

1. **先修度量，再做对比。** KPC 与 gold_evidence 的匹配口径问题会让"生成质量"与"检索命中"同时失真，必须在进入对比实验前修正，否则所有实验结论都建立在有偏的尺子上。
2. **优先验证 embedding 假设**（E2-embed）。它是唯一"零代码改动、只需重建索引"就能验证的根因，且证据最硬。
3. **其次做 Rerank**（E1-rerank）。召回上限 0.867 已经把可达空间摆在那里，Rerank 是把上限兑现在 top-5 上的最直接手段。
4. **对比型问题是对后续优化的试金石**：检索命中 0.50 但 KPC 0.12，是"检索到 ≠ 答得出"的典型，Query Rewrite 与对比型专用 prompt 应当以它为验证对象。
5. **计算题不作为主战场**，单列说明 OCR 局限，避免结论被语料缺陷掩盖。
6. 报告中的所有"改进预期"都必须在 `experiment_design.md` 第 1.4 节的预设判据下检验；**提升 < 5pp 或 bootstrap 区间跨 0 的策略，将如实报告为无效**。

## 十一、度量口径修正建议（前置工作）

| 问题 | 现状 | 建议改法 |
|---|---|---|
| gold_evidence 逐字匹配 | 证据字符串必须在 chunk 内逐字出现（归一化去标点后），切分边界错位即判未命中；且"排名 > 10"被统一归为检索失败 | ① 标注升级为 **chunk 级**（直接标注 gold chunk_id）；② 或允许 ±1 chunk 邻域命中；③ 评测 `max_k` 提高到 20–50，使 retrieval_miss / rank_miss 分类真实反映原因 |
| KeyPointCoverage 逐字匹配 | 关键词字符串包含判定，对改写/缩写零容忍，实测 3/5 例误判 | ① key_points 扩充同义词表并做归一化；② 或改为"关键点嵌入相似度 ≥ 阈值"；③ 或引入 LLM 裁判并对 30 题人工双标注校准（报告 Cohen's kappa） |
| 缺少忠实度指标 | 仅 KPC + CitationRate，无法直接回答"是否幻觉" | 引入 Faithfulness（RAGAS + 本地裁判 + 人工抽检校准） |
| 单次运行无方差 | temperature=0 保证可复现，但无法给出指标波动范围 | 对差值接近判据阈值的实验补 3 次重复；报告 bootstrap 置信区间 |
| 失败分类依赖答案质量 | `classify_failure` 用 KPC < 0.6 判定生成失败，继承 KPC 的口径缺陷 | 口径修正后重跑分类，失败分布需重算 |

## 十二、局限与待验证

1. **样本量 30 题**：单题权重 3.3%，个别题目的判分波动会影响结论方向；计划中期前扩充到 150–300 题（v2.0）后复算本报告全部表格。
2. **诊断脚本未入库**（k=100 复算、距离比对为本次临时分析）：建议以 `scripts/` 下的正式脚本形式入库，纳入可复现链路。
3. **30 题质检只验证了 gold_evidence 能在语料中命中，未验证"该证据足以回答问题"**：q027 三条跨章证据是否构成完整答题链，需要人工复核后调整。
4. **单次评测、单一模型**：仅 qwen3:4b，未与更强模型对照，无法区分"检索问题"与"小模型能力问题"；建议补一组更大模型的生成对照（可作为 E0 的扩展）。
